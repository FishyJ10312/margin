# 留白 0.5：模型接入与艺术边框改进说明

## 现在接入的是什么

现在是一个受约束的设计参数生成流程：一张照片缩略图 + 设计要求 + 实际留白几何 → 一次 Codex 调用 → 三套 JSON 设计 → Rust 本机绘制 → 用户选择。

本机 Codex 指本机安装的 Codex CLI。留白复用它已有的账户登录，由 CLI 连接模型服务进行推理，会使用对应账户的额度。没有操控 Codex 桌面窗口、读取这段聊天，也没有显式调用你以前安装的设计 Skill。不是完全离线的 AI；离线的是普通加框、水印、模板复用和图片导出。

这次本机实测的 CLI 版本为 0.169.0-alpha.11.1。软件不内置 Codex CLI，模型名称留空时交给 CLI 使用默认值。

## 一次生成的实际步骤

1. 用户打开智能配框，软件用本机核心纠正照片方向、转为 SDR sRGB，生成最长边 768 px、保持比例的 JPEG 缩略图，去掉原始元数据。
2. 界面展示将发送的缩略图。只有用户勾选相应模型入口的同意项、点击生成，才发送图片。不会把整批照片逐张发送，也不附带照片目录、署名、字体文件或导出队列。
3. 软件计算最终画布尺寸、照片矩形在画布内的位置，换算为 0–1000 的坐标；连同边框百分比、用户写的风格方向、密度和界面语言交给模型。当前比例和边框百分比保持由用户控制。
4. Codex 在临时目录运行。主要参数包括 `exec --ignore-user-config --ephemeral --sandbox read-only --skip-git-repo-check`、`--image`、`--output-schema`、`--output-last-message`。关闭 shell_tool、multi_agent、view_image 和网页搜索，禁用项目文档注入；通过进程参数传递，不用 shell 拼接命令。取消时终止子进程并清理临时目录。
5. 输入的系统设计说明要求忽略照片里出现的指令，只围绕照片设计边框。应用自己没有读取、拼接设计 Skill 的步骤，也没有授予模型修改项目文件的任务。
6. 模型返回三套方案，每套含名称、理由、边框色、基础纹样，以及有界的曲线、折线和图案参数。生成 Schema 为 1–36 个元素；原生场景校验上限为 48。支持曲线、折线及星星、光芒、爱心、云朵、树叶、小鱼、小猫、花、圆形九种基础图案。不是任意 SVG、HTML、脚本，也不是一张 AI 画出的完整插画图片。
7. 软件检查颜色、数值、类型和控制点，限制结果大小为 256 KiB。Rust 用 tiny-skia 按 256 px 小块绘制，照片区域通过蒙版保护，装饰仅出现在边框。三套预览使用与导出相同的核心。
8. 用户选择应用、撤销或保存模板。模板记录比例、边框、配色、纹样和艺术场景；后续复用直接在本机绘制，不再请求模型、不再消耗生成额度。

整个模型任务最长 180 秒，兼容 API 请求最长 160 秒，不自动重试。取消不等于服务商一定停止计费。复用 Codex 账户时会移除继承环境中的 OPENAI_API_KEY/CODEX_API_KEY，避免意外改用这两个环境变量指定的 API 付费方式；账户认证仍由已有 Codex 登录处理。

## 另一个入口：兼容视觉 API

可填写 Base URL、模型名与 API Key；使用 Chat Completions 的 image_url Base64 JPEG 输入格式。需要支持图片输入与 max_tokens。远程地址要求 HTTPS，本机 localhost 可用 HTTP，不自动跟随重定向。

API Key 只在当前应用会话内保留，不写入个人预设、模板或配置文件；Base URL 和模型名可以保存。这是视觉模型生成 JSON 的接口，不能把任意文生图服务地址填入后就获得水彩或插画素材。真正的图像生成需要单独的适配器、额度提示与素材处理流程。

## 为什么效果仍然粗糙

- 可用图形太基础。模型只能在这套有限的几何语言里表达，复杂卡通、真实手绘、水彩和纸张笔触无法靠多摆几个小鱼、星星实现。
- 旧流程没给出实际画布和照片位置，容易把元素摆在最后被照片遮住的地方，或者沿固定上下边条堆图案。这次已经补上实际几何。
- 旧规则强制至少六个元素，并同时放曲线和图标，会把纯线条设计变成凑数拼贴。这次已经取消，允许一条或少量曲线组成的方案。
- 当前没有视觉复审。模型产生坐标后，看不到真正合成的成品；参数有效不代表画面好看，也不会自动发现线条节奏差、视觉重心分散、图形被截断等问题。
- 只有“简约/适中/丰富”还不够。专业设计还需要主次、疏密、笔触、色彩关系与跨方案的一致视觉语言。
- 模板目前使用全画布归一化坐标。换照片长宽比时，照片矩形会变化，部分图案可能被蒙版遮住；还没有按上、下、左、右边框区域绑定的自适应锚点。

所以这版能画出真实线条和卡通元素，但还不能保证每次都得到成熟的艺术设计。

## 建议的完善顺序

### 1. 先做有质量的风格模板库

先打磨 8–12 套完整的构图语言，例如双线环绕、角落植物、旅行手账、海洋流线、童趣贴纸、编辑式几何。每套统一笔触、主色、点缀色、留白比例和视觉重心。模型负责选模板、提取配色、挑选主题元素和少量调整，不必每次从坐标零开始。用户现有模板也能作为起点。

这是最优先的提升：质量更稳定、调用更少，软件仍轻量。增加图案数量本身不会带来设计质量。

### 2. 再加可选的“生成—查看成品—修改”

第一轮返回三个方案 → 本机生成低分辨率实际成品与对照图 → 第二轮视觉模型检查并只返回修改后的 JSON → 本机重新绘制。检查重点为照片遮挡、裁断、线条节奏、色彩对比、视觉重心和用户要求。

建议默认一轮；用户选择“精修一次”时，明确显示将增加一次模型调用，最多两轮、可取消，不自动无限重试。直接传回合成缩略图即可，无需把全尺寸照片或整批照片交给模型。当前 0.5 尚未实现这一复审步骤。

### 3. 做真正适配照片的模板几何

每个图案记录所属边框区域、相对锚点和与照片边缘的距离，曲线绑定边框路径。换横竖图或最终比例时按区域重排。对窄边框简化或隐藏次要装饰，避免简单地缩放整套画布。这部分比继续增加通用图标更重要。

### 4. 将设计方向变成可控制的参数

在自由描述之外，提供风格、元素主题、线条粗细、曲线程度、配色跟随照片的强度、装饰集中位置，以及“不要哪些元素”。允许在已有方案上输入“只保留线条”“把装饰集中到左下角”“颜色再淡一点”，保留其余构图。

### 5. 最后再考虑生成插画或材质

水彩、真实手绘、复杂角色等使用独立的图像生成接口；生成仅边框素材或透明元素，放进本地素材库。需要独立说明额度、耗时和授权，限制尺寸、解码内存并保留照片蒙版。图像生成与目前 Codex 的 JSON 设计接口是两条不同能力，不应混成一个含糊按钮。

### 6. 建立质量检查和可见进度

本地检查加入元素可见面积、裁断、边框墨量和对比度，保留现有类型/参数/蒙版检查。界面分为准备照片、生成、绘制预览、可选精修四个阶段；记录模型、耗时、轮数和失败原因，避免记录私密照片、API Key 或完整敏感提示词。美术质量最终仍由用户选择，不能只靠元素数或程序评分。

## 本次完成与证据边界

0.5 已完成：实际几何输入、保持用户比例与边框、允许简约纯线条、可保存复用的模板库、真实水印局部合成、完整适应预览、三种内置中文字体和中英文界面。

本次真实 Codex 调用只使用程序生成的测试风景图，一次约 50.3 秒，返回三套含 10/11/11 个元素的设计；本机实际导出了 PNG。它证明登录、传图、结构化返回和本机绘制走通，不证明任意风格的设计质量。最后一次放宽图案数量规则通过了本地测试；没有为这一规则重复消耗一次真实调用。没有发送用户的私人照片做 AI 验收。
